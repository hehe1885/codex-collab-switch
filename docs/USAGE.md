# 使用示例与常见问题

## 1. 只想用当前模型

安装后直接发普通任务即可，不需要先开启再关闭。若当前对话已经开启过协同，输入：

```text
$codex-collab-switch 退出协同
```

之后普通任务由当前主模型独立执行。退出不改变界面选择的主模型或其思考强度，也不会清空已保存的执行偏好。

## 2. 首次开启并选择参数

```text
用户：$codex-collab-switch 开启协同
助手：展示当前可指定为执行代理的模型。
用户：选择一个型号。
助手：展示这个型号支持的思考强度。
用户：high。
助手：确认执行模型完整 ID、强度 high，以及仅当前对话生效。
```

若客户端没有模型列表，不应凭记忆列出型号。助手会说明限制，并要求完整型号和强度；若也无法显式传递这些参数，就不能启用协同。

## 3. 一句话指定型号和强度

以下假设运行环境包含 `gpt-6-luna` 且支持 `high`：

```text
用户：$codex-collab-switch 开启协同，6luna，high。
助手：已开启协同：主模型沿用当前对话，执行模型 gpt-6-luna，思考强度 high。仅当前对话生效。
```

`6luna` 是唯一对应现有型号的简称，所以不重复询问。示例中的型号不是内置默认值，不可据此推断未来也存在。

## 4. 拼错了名称或版本

假设实际只有 `gpt-6-luna`，没有 `gpt-6.1-luna`：

```text
用户：开启协同，6.1luna，high。
助手：没有找到 6.1 Luna，你是不是指 gpt-6-luna，思考强度 high？
用户：对。
助手：确认并开启。
```

假设存在 `gpt-6.1-terra`，输入 `6.1terre` 时同样先确认。用户否认候选时继续选择，不能直接启动猜测的模型。

## 5. 名称不明确或强度不支持

`sol` 同时匹配多个版本时，应列出候选让用户选。选定模型后，如果用户要求的强度不支持，应列出真实支持的强度。两种情况都要先消除歧义再委派。

## 6. 保存与更换默认执行组合

```text
用户：把刚才确认的型号和 high 保存为默认组合。
助手：写入偏好文件，并报告是否保存成功。
```

下次用户显式开启时，可以使用仍然有效的组合，并显示完整参数。可以说“将默认执行组合改成……”，也可以仅在本次指定其他型号。保存偏好本身不会开启协同；新模型发布不会自动修改旧偏好。

## 7. 协同执行时会发生什么

主模型理解需求，确定任务边界和验收标准。较小任务可以直接完成；实质性任务交给一个明确配置的执行代理，传入独立、完整的任务说明。主模型审查文件改动和验证结果，有问题则让同一代理做针对性修正。

执行代理不是多个并发写入者。工作流不允许用未配置的默认代理替代已选择的组合，也不把完整聊天历史当作唯一交接材料。

## 8. 任务进行中退出

明确要求退出后，先禁止新委派。若执行代理还在运行，助手会请求中断，检查状态及已有改动，确认文件写入停止后再接手。若客户端不支持停止或未确认停止，助手应明确说明并等待，不同时改相同文件。已经产生的改动不会被自动删除。

## 常见问题

### 安装后怎么没出现？

检查 Codex 读取的个人 Skill 目录，必要时使用 Legacy 安装路径并重启 Codex。不要同时在两个目录安装同名 Skill。桌面版从 Skill 选择器选择 `codex-collab-switch`；Codex CLI / IDE 扩展可输入 `$` 选择 Skill。本文不要求使用 `@` 调用。

### 为什么直接说“开启协同”没有加载？

Skill 配置为仅显式调用。第一次使用请显式选择 `codex-collab-switch`；自然语言命令主要用于 Skill 已加载的当前对话。安装不会自动把其全文注入每个普通任务。

### 为什么选了新模型却没有对应执行模型？

主模型选项和子代理可用选项可能不同。只有运行环境明确允许作为子代理调用的型号，才会进入可用候选。不能根据主模型名称推测同系列执行模型存在。

### 为什么升级 Skill 后旧项目仍然协同？

原版曾将规则写入项目指令文件，卸载 Skill 不会删除这些规则。按 [迁移说明](../MIGRATION.md) 清理旧托管区块。双 Skill 试用版用户也要先卸载旧名称，避免残留。

### 新对话或分叉会继承吗？

普通新对话默认独立；本 Skill 不保存开启状态。分叉/复制对话可能带入历史指令，只有客户端暴露足够身份信息时才能识别并要求重新开启。无法识别时不能承诺绝对隔离。

### 退出后会自动切换回某个 Sol 版本吗？

不会。独立模式使用当前对话主模型，与 Sol、Luna 或具体版本无关。
